## 2. Jackson 3.1.5 → 3.3.0 — требует изменений

### Почему обновлять обязательно
3.2.4 закрывает две CVE (CVE-2026-110879, CVE-2026-110729). Остаться на 3.1.x нельзя.
3.2.4 падает на тех же тестах, что и 3.3.0, поэтому сразу целимся в 3.3.0.

Попутно: коммит `04547b4` назывался «upgrade to Jackson 3.2.2», но в каталоге осталось
`jackson = "3.1.5"` — обновление фактически не было применено.

### Что сломалось
Два parity-теста в `max-bot-api-gson` (`SerializerParityTest.coercionsReadLikeJackson`):
Jackson перестал принимать строки `" -Infinity "` и `"0x1p3"` для `double`, а Gson их
по-прежнему принимает. Источник — проверка числовых строк при приведении String→double
(jackson-databind #6179 в 3.2.3, #6232 в 3.2.4).

Код самого Jackson-адаптера менять не нужно: это изменение поведения библиотеки. Но Gson-адаптер
обязан вести себя так же (это его контракт), значит правится Gson.

### Как Jackson 3.3.0 читает строку в `double`/`Double` (проверено на 3.3.0)
| Вход | 3.3.0 | Сейчас в Gson |
|---|---|---|
| `"NaN"`, `"Infinity"`, `"-Infinity"`, `"+Infinity"`, `"INF"` | читается | `"+Infinity"`, `"INF"` → **ошибка** |
| `" NaN "`, `" -Infinity "` (с пробелами) | **ошибка** | читается |
| `"-NaN"` | ошибка | ошибка |
| `" 1.25 "`, `"+1.5"`, `".5"`, `"5."`, `"1e2"` | читается (пробелы обрезаются) | читается |
| `"0x1p3"`, `"1d"`, `"1f"`, `"1_000"` | **ошибка** | читается |
| `""`, `" "` | 0.0 / null | 0.0 / null |
| число `1e400` | Infinity | Infinity |
| число `1.` (токен, не строка) | ошибка парсера | проверить |

Для целых (`long/int`) поведение не изменилось — эти parity-кейсы прошли.

### Что сделать
1. `max-bot-api-gson/.../LenientPrimitiveAdapters.DoubleAdapter.read`, ветка `STRING`:
   - сначала сравнить **необрезанный** текст со специальными значениями Jackson:
     `NaN`, `Infinity`, `+Infinity`, `-Infinity`, `INF` (при реализации проверить ещё
     `+INF`, `-INF` пробным прогоном на 3.3.0);
   - иначе обрезать пробелы; пустая строка → значение по умолчанию (как сейчас);
   - иначе текст должен соответствовать десятичной записи
     `[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?`, затем `Double.parseDouble`; всё остальное —
     ошибка;
   - проверить, есть ли у Jackson ограничение длины числовой строки
     (`StreamReadConstraints.maxNumberLength`, по умолчанию 1000) при приведении; если да —
     повторить его.
2. `SerializerParityTest`:
   - перенести `" -Infinity "` и `"0x1p3"` из `coercions()` в `edgeCases()`;
   - добавить: `"+Infinity"`, `"INF"`, `" NaN "`, `"1d"`, `"1_000"`, `".5"`, `"5."`, очень
     длинную числовую строку, числовой токен `1.`.
3. Обновить javadoc `LenientPrimitiveAdapters` и `GsonMaxSerializer` (правила для double).
4. Release notes: **изменение поведения для пользователей обоих адаптеров** — строки
   `" NaN "`, `"0x1p3"`, `"1d"` в числовых полях теперь ошибка (в Jackson — из-за самой
   библиотеки, в Gson — для совпадения с ним). Для реального API MAX это граничные случаи.
5. Проверить, что Spring Boot стартер работает с Jackson 3.3.0: `spring-boot-starter-webmvc`
   4.1.x приносит Jackson 3.1.x, Gradle поднимет его до 3.3.0. Тесты `max-bot-api-spring-boot`
   в пробном прогоне прошли; дополнительно посмотреть
   `./gradlew :max-bot-api-spring-boot:dependencyInsight --dependency jackson-databind`.
6. Прогон: `./gradlew check` (оба набора — `test` и `testGson`).

Прочее из release notes 3.2–3.3, что нас **не** затрагивает: обработка отсутствующих
примитивов (#5734 — у нас `FAIL_ON_NULL_FOR_PRIMITIVES` выключен), `Shape.ARRAY` с records
(#6043), `NON_DEFAULT`/views/`convertValue` (#6219, #6068, #6275), более строгая проверка
UTF-8 (core #1782/#1795 — совпадает по духу с Gson 2.15).

Оценка: ~0.5 дня, риск средний (затрагивает контракт совпадения адаптеров).
